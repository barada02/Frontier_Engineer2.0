The problem

A missed bug costs you one bug.
A wrong finding costs you the tool.

Trust a correct finding earnsa little
Trust a wrong finding burnsmost of it

Checking a false alarm takes a developer just as long as checking a real bug. After a few of those, people stop reading. So what matters here is precision — the share of findings that hold up — not recall, the share of bugs found.

The gap

It looked like an 80% reviewer.

12Findings claimed
9Backed by a test that discriminates
3Proved nothing

The usual way to score a reviewer is to ask whether it named the right file. That gives 80%. Ask instead whether its findings hold up, and it drops to 60%. It also reported a bug in one refactor that was perfectly correct.

It can read the repository, and it can run its own test.

The important choice is that run_proof_test returns raw pytest output. An import error means the agent's own test is broken. An assertion failure means the code is. The agent has to tell those two apart by itself, and that is the whole difference between a real finding and noise.

Ground truth

The answer key is written by human maintainers.

A real commit fixes source code

Revert it the defect returns

The deleted test becomes the oracle

A commit only becomes a case if its deleted test can tell the two versions apart: it must fail on the bug and pass on the fix. 15 of 17 survived. The rejects matter — plenty of commits say “fix” but ship a test that passes either way.

Improvement changelog

Four iterations. One of them went backwards.

00 One prompt with the diff. No tools, no repository. 60.0% Baseline
01 Gave the agent the repository to read. 73.3% Kept · biggest gain
02 Let it run its own candidate test. Ran twice. 73.3 / 66.7% Kept · shipped
03 Required proof before any finding could be reported. 66.7% Removed
04 Raised the step ceiling to isolate the cause. 73.3% Diagnosis only

Reading the repository did not make the agent smarter. It named the same files and made the same claims as before. Those claims just started holding up.

Hot take

A verification requirement is not free. It spends the same budget the agent needs to investigate.

Three runs hit the step limit while they were still investigating, after 11, 15 and 16 proof attempts. They never reached a conclusion. The harness recorded that silence as “no bug found” — which looks exactly like the agent deciding the code was fine.
